Here is the developer handoff in English.

  Goal
  Make V3 quickReply CTA buttons deterministic for selected cases, instead of letting the LLM composer freely generate many unrelated
  buttons.

  Do not port legacy regex rules directly. Use V3 intent, flow_state, slots, tool_results, and guard_id to decide which CTA buttons should
  appear.

  Current V3 Behavior

  - General quickReply buttons are generated by the LLM composer in chat_v3/composer.py.
  - Final quickReply events are normalized by policies/cta_registry.py.
  - If a button label is registered in cta_registry.py, the registry can attach url, cta_action, and metadata automatically.
  - The registry should remain a validation/normalization layer, not the place that decides when a CTA should appear.

  Recommended Implementation
  Create a deterministic CTA helper:

  # tstation-ai/app/tstation-ai/services/tstation/chat_v3/quick_replies.py

  def fixed_quick_replies(
      *,
      decision: RouteDecision,
      slots: ConversationSlots,
      tool_results: list[dict],
      guard_id: str | None = None,
  ) -> list[dict]:
      ...

  Then call it in chat_v3/service.py before composer.suggest_quick_replies():

  fixed_chips = fixed_quick_replies(
      decision=decision,
      slots=slots,
      tool_results=tool_results,
      guard_id=guard_id,
  )

  if fixed_chips:
      chips = fixed_chips
  else:
      chips = await composer.suggest_quick_replies(...)

  Even when fixed CTAs are generated, still pass the final quickReply event through normalize_quick_reply_event(). That step attaches
  registered URLs, cta_action, and metadata.

  Important Constraints

  - If the bot is asking for tire quantity, show only:
      - 1개, 2개, 3개, 4개

  - During slot-fill turns, do not show unrelated CTA buttons.
  - If a rich template card is emitted, do not call the general quickReply composer.
  - Do not emit ORDER_HISTORY_DETAIL unless ord_no is available.
  - Do not emit STORE_DETAIL unless shop_seq is available.
  - shop_id and shop_seq are different. Store detail URLs must use shop_seq.
  - Do not use regex-only intent detection. Use V3 router/contract/flow-state results.

  Test Cases to Add

  1. Quantity question emits only 1개, 2개, 3개, 4개.
  2. Coupon issue guard emits 쿠폰함 바로가기 with URL.
  3. Warranty intent emits 나의 워런티 확인 with URL.
  4. Order detail guidance with ord_no emits ORDER_HISTORY_DETAIL with the actual order number substituted.
  5. If ord_no is missing, do not emit order detail CTA.
  6. If shop_seq is missing, do not emit store detail CTA.
  7. For generic answers with no fixed CTA rule, composer may return an empty list and should not invent unrelated buttons.

  Core Principle
  V3 should decide CTA visibility deterministically from flow state, intent, slots, and tool results.
  cta_registry.py should only attach URLs/actions/metadata and validate final chips.
